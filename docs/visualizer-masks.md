# Mask library

Spatial-control material for the visualizer: inkblots, emblems, silhouettes, and hand-authored boundary
shapes. The visualizer converts a mask into a signed distance field, gradient field, and stencil, then
shares that derivation across every consumer in a scene.

Masks are same-origin so mask textures raise no cross-origin tainting question, and the library is
versioned with the code that reads it, so collision and containment behavior remains stable across
deployments even though scene selection itself is not repeatable. See
[ADR-0005](./adr/0005-visualizer-mask-assets.md).

`manifest.json` is the index. An empty `masks` array is valid: mask-driven plugins declare
`requiredAssets: ['mask']` and stay inactive until the library has entries, so the visualizer works with
no masks at all.

## Adding a mask

Masks are generated by the `mask` asset type in [`../../illuminator`](../../illuminator).
Add the asset to a pack under `masks/`, generate and process it, then copy the processed PNG to
`frontend/public/masks/` and add a manifest entry:

```json
{
  "id": "inkblot-symmetric",
  "file": "inkblot-symmetric.png",
  "interpretation": "luminance",
  "mirror": true,
  "tags": ["organic", "rorschach"]
}
```

| Field | Meaning |
| ----- | ------- |
| `id` | Stable identifier. Becomes the asset id `mask:<id>`. |
| `file` | PNG filename in this directory. |
| `interpretation` | `luminance`, `alpha`, or `threshold` — how the mask value is read. |
| `invert` | Treats dark as inside rather than light. |
| `mirror` | Permits symmetry transforms to anchor on the mask. |
| `tile` | Permits the mask to repeat rather than being framed once. |
| `tags` | Free-form hints a theme may prefer. |

The processed output is single-channel grayscale at 1024×1024, range-normalized, with the shape bright
and the surround dark. Entries that do not parse are dropped individually, so one bad entry does not
cost the whole library.
