# 0009 — Scene selection treats a loaded asset as a producer

- Status: Accepted
- Date: 2026-07-25

## Context

Mask assets are authored in `assets/visualizer-masks/`, generated by `illuminator`, committed to
`frontend/public/masks/` with a manifest, deployed through the static origin, fetched by the kernel,
and uploaded as GL textures. Specification section 12.2 lists nine things a mask should control, and
`plugins/fields/mask-fields.ts` implements four plugins to do it.

None of them could ever be selected.

`inputsSatisfiable` in the scheduler decides whether a candidate's required inputs can be met, and it
built its set of available port types from the outputs of already-chosen plugins alone. No plugin
produces a `mask-texture` — a mask comes from the host, not from the graph — so `MaskSignedDistanceField`
was permanently unsatisfiable, and with it everything downstream that reads a distance field.

Wiring already knew better: `wireScene` falls back to `findAsset` when no plugin output matches, and
`compileGraph` binds asset resources separately from edges precisely because an asset has no place in
execution order. The knowledge existed one stage too late. Selection rejected the plugin before wiring
ever got the chance to satisfy it.

The failure was invisible because every test that exercised mask plugins built its graph by naming
plugins explicitly and calling `wireScene` directly, which works. Nothing asserted that scene
*assembly* could produce one.

## Decision

`SchedulerContext` carries the port types its assets can bind to alongside the ids it already carried
for `requiredAssets`, and `inputsSatisfiable` seeds its produced-type set from them.

The types are declared structurally as `{ type: PortType }[]` rather than as wiring's `AssetResource`,
so selection gains no dependency on the wiring module to know that a loaded mask satisfies a mask
input.

## Consequences

Mask-derived plugins appear in assembled scenes, so the mask pipeline delivers the dimensions section
12.2 describes rather than only being able to.

The candidate pool widens whenever an asset is loaded, which is the intent — album art and masks are
optional material that should broaden what a scene can be, not a separate mode.

Asset ids and asset types are now both part of scheduler context and have to stay in step. The host
already derives both from the same `VisualAsset` list, so they are two projections of one source
rather than two things to keep synchronised.

Reachability is asserted by scene assembly rather than by hand-wired graphs: a plugin whose only
producer is an asset must appear in scenes the scheduler builds, and must not appear when the asset is
absent. Testing the wiring alone is what let this stay hidden.
