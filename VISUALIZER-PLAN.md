# Modular WebGL Music Visualizer — Implementation Plan

Build the microkernel-plus-plugin-graph visualizer described in the spec as a new subsystem at
`frontend/src/visualizer/`, driven by a read-only Web Audio tap on the existing sticky player and
loaded as a dynamic chunk on activation. Scope is the spec's §24 initial production scope: the
kernel foundation plus the ~36 named initial plugins across sources, fields, simulation,
transformers, and composition. Secondary and deferred plugin families are recorded in
[`docs/backlog.md`](./docs/backlog.md) and are out of scope here. Playback correctness outranks
visual capability throughout: no phase may leave the audio path able to degrade.

## Confirmed decisions

- Scope is the full §24 initial production scope, not a thin slice.
- The rendering layer is raw WebGL2 behind a small in-repo device helper. No three.js, twgl, or regl.
- WebGL2 with `EXT_color_buffer_float` is a hard floor. Below it the visualizer reports unavailable.
- The visualizer is off for a first-time visitor. The opt-in is persisted, and no `AudioContext` or
  media-element tap exists until it is enabled.
- The thumbnail beside the player timeline shows static release artwork. The kernel runs only while
  the expanded modal is open, and stops when it closes.
- The visualizer is not offered when the native-HLS playback path is in use.
- Audio analysis runs in an AudioWorklet on the audio render thread, not by polling an analyser on
  the main thread.
- Worklet-to-main transport is decimated `postMessage` snapshots, not a `SharedArrayBuffer` ring
  buffer. A SAB needs `crossOriginIsolated`, which needs COOP and COEP response headers, which the
  shared Ahara `website` module exposes no input for — and enabling COEP would additionally break
  the Tailwind CDN script in `frontend/index.html`. Snapshot cadence is a tuning value; per-render-
  quantum messaging is not viable.
- HLS forward-buffer length is a first-class input to the performance controller alongside frame time.
- Masks are generated by `../illuminator` under a new `mask` asset type and committed to
  `frontend/public/masks/` with a manifest.
- The subsystem lives at `frontend/src/visualizer/` split into `core/`, `host/`, `plugins/`, `ui/`.
- Diagnostics are a `?viz-debug=1` overlay. `prefers-reduced-motion` selects a low-energy profile.

## Context / reuse map

Source of truth for the requirements is [`docs/visualizer-spec.md`](./docs/visualizer-spec.md).
Section numbers below refer to it.

**Reused as-is.** The player is not restructured. `frontend/src/music/MusicPlayerContext.tsx`
already owns the single `<audio>` element mounted once at the public app root (never remounted
across navigation), carries `crossOrigin="anonymous"` on it, resolves playback sources, and holds
the `pendingRestoreRef` restore path and the `[releaseManifest, selectedSource, selectedTrack]`
effect that fires on track change — the natural home for the clock's generation bump. Its
`hls.js/light` dynamic import is the precedent for lazy-loading the visualizer chunk.
`frontend/src/music/StickyPlayer.tsx` supplies the `bottom-player__timeline` slot the thumbnail sits
beside, and the whole player surface is plain BEM CSS in `frontend/src/App.css` — not Tailwind — so
visualizer styling extends the existing convention. `frontend/src/player-analytics.ts` is the
pattern to follow if visualizer telemetry is wanted.

**Reused but retuned.** Media CORS is already correct for analysis and for artwork used as a GL
texture: `infrastructure/terraform/media_storage.tf` sets bucket CORS across all four hostnames plus
`localhost:3000`, and `infrastructure/terraform/media_cdn.tf` forwards the CORS request headers on
every cache behavior. No infrastructure change is needed, but the artwork fetch path needs a
texture-upload route distinct from the `<img>` path the player uses today. `hls.js` exposes
`FRAG_BUFFERED`, `BUFFER_STALLED_ERROR`, and `mainForwardBufferInfo`; the instance is currently
local to an effect closure and must be surfaced for buffer telemetry.

**Built new.** Everything under `frontend/src/visualizer/`, whose directory READMEs describe each
tier's intended contents. In `../illuminator`, a `mask` asset type: union entry in `src/types.ts`,
allowed set and `resolve_asset_type` and `process_mask` in `post/process.py` (whose `process_one`
dispatch at line 506 is the extension point, with `process_hex_tile` as the nearest model), and a
type prompt fragment.

**Decisions.** [ADR-0001](./docs/adr/0001-visualizer-audio-tap-policy.md) audio tap policy,
[ADR-0002](./docs/adr/0002-visualizer-webgl2-floor.md) WebGL2 floor and raw GL,
[ADR-0003](./docs/adr/0003-visualizer-pure-core-thin-shell.md) pure core and thin shell,
[ADR-0004](./docs/adr/0004-visualizer-playback-supremacy.md) buffer-health throttling,
[ADR-0005](./docs/adr/0005-visualizer-mask-assets.md) mask assets.

## Cross-cutting constraints

These apply to every phase. The durable ones are recorded as critical rules in
[`AGENTS.md`](./AGENTS.md).

1. **Playback supremacy.** Audio flows `source → gain(1.0) → destination` unconditionally, with the
   analyser on a parallel branch that terminates in nothing. No visualizer failure — shader, plugin,
   graph, or analysis — can reach the output. Playback remains fully functional with the visualizer
   broken or absent.
2. **The tap is irreversible and lazy.** One tap per element for the page's lifetime, created on
   first activation, never on the native-HLS path.
3. **Pure core, thin shell.** Every decision rule is a pure module over plain data, unit-tested in
   the Node environment (`make ci` runs Vitest with no environment override). The host shell holds
   no decisions. This is what makes the clock, grammar, and perf ladder verifiable without a browser.
4. **Playback-authoritative time.** `requestAnimationFrame` schedules frames and contributes nothing
   to visual time. Freeze semantics are enforced centrally in the clock, not per plugin.
5. **The kernel knows no effects.** It understands capabilities, port types, declared costs,
   dependencies, compatibility, lifecycle state, and scheduling metadata. Registering a plugin never
   requires a kernel change.
6. **Resource discipline (§21.3).** No per-frame shader compilation or asset decode, no unbounded
   textures or temporal history, no continuous main-thread allocation, no full device-pixel
   rendering on high-DPI displays. Rendering stops when the page is hidden.
7. **Determinism.** A scene is reproducible from its seed, which is what makes the diagnostics
   overlay and any visual bug report useful.
8. **One stylesheet.** The Vite build sets `cssCodeSplit: false` because the `website` module is
   configured with a single `ENTRY_CSS`. Visualizer styles join that graph; they never add an entry.
9. **Audio feature work is never duplicated in plugins.** Extraction, normalization, and beat
   detection are kernel services consumed through the feature bus.

## Milestones

### M0 — Audio spine and playback clock

Everything about time and audio, with no pixels. Establishes on day one whether analysis is viable
per platform, which is the only finding that can invalidate later phases.

- Availability gate: native-HLS path detection, WebGL2 and `EXT_color_buffer_float` probe,
  reduced-motion, persisted opt-in.
- The lazy tap and its parallel dead-end analyser branch, context resume tied to the existing play
  gesture, and the dead-analysis watchdog.
- AudioWorklet processor computing bands, RMS, peak, spectral centroid, spectral flux, onsets, and
  beat tracking on the audio render thread, posting timestamped events; output-latency compensation
  from `outputLatency` plus `baseLatency`, with a constant fallback where `outputLatency` is absent.
- The feature bus, beat-phase envelope shapes (§7.2), and parameter-binding evaluation (§7.3).
- The playback clock state machine (§6) with freeze semantics for pause, stall, seek, and track
  change, including generation bumping, stale-event clearing, and false-onset suppression on resume.
- A temporary text readout of clock state and normalized features, sufficient to verify by ear.
- **[DECISION]** Onset sensitivity, beat-tracker confidence thresholds, and envelope defaults are
  tuning by ear against real tracks, not values the plan can pick.
- Exit: `make ci` green; clock and feature modules unit-tested against synthetic buffers and
  scripted event sequences; readout tracks audible music across pause, seek, buffering, and track
  change; audio verified unaffected with the tap active and with the visualizer never enabled;
  Safari and iOS correctly report unavailable.

### M1 — Render spine and first pixels  [depends on M0]

The whole path from a plugin definition to a composited frame, proven by the smallest scene that
exercises it.

- WebGL2 device: capability probe, program cache, framebuffer pool, fullscreen-quad passes, context
  loss and restoration rebuilding GPU state from retained plugin and asset metadata.
- Typed render graph: port types (§9.1), connection validation, topological compilation, feedback
  cycle legality, intermediate resource lifetimes, shared derived-resource reuse (§13).
- Layer model and compositor (§11): order, blend modes, masking, feedback injection, crossfades,
  final output routing, and the feedback ping-pong buffers.
- Plugin contract and registry (§9): definition shape, instance lifecycle, cost and character
  metadata.
- Three plugins end to end — `SignalTraceSource`, `FeedbackFlowTransform`, `ToneMapper` — wired by
  hand, no scheduler.
- **[DECISION]** How a plugin expresses GPU work: either it authors GLSL and issues its own draw
  calls against the device helper, or it returns a declarative pass descriptor — shader, uniforms,
  input bindings, output target — that the runtime executes. The declarative form keeps plugin
  definitions as plain data, so pass structure becomes unit-testable and the performance controller
  can rewrite resolution and pass count without plugin cooperation; the imperative form is more
  direct for the geometry and particle plugins that do not fit a fullscreen-quad shape. This choice
  determines how all ~30 remaining plugins are written, so a wrong call here is paid back in M5.
- Exit: `make ci` green; graph validation and compilation unit-tested including rejection of invalid
  connections and illegal cycles; the hand-wired scene renders and reacts to audible audio, freezes
  correctly on pause and seek, and survives a forced context loss.

### M2 — Scene intelligence and performance budgeting  [depends on M1]

The pure-logic layer that decides what runs and what it may cost. Grouped together because both are
`core/` state machines over the same telemetry, and a scheduler without a budget picks scenes the
device cannot render.

- Activation scheduler (§14): asset availability, plugin history, compatibility, cooldowns,
  activation weights, seeded deterministic selection.
- Scene grammar (§15) and character-based assembly (§9.3), including the dominant-plugin and
  high-cost caps and the visual families.
- Themes (§16) as weighted constraint sets, and visual state serialization.
- Mutation model (§17) at parameter, plugin, branch, and scene granularity, preserving unrelated
  plugin state across a swap.
- Deactivation policies (§18): immediate, fade, drain, freeze-and-dissolve, handoff-feedback.
- Performance controller (§21): adaptive quality profile, the ordered downgrade ladder, conservative
  recovery, and HLS buffer health as a first-class input beside frame time, including suspend at the
  floor.
- Audio-mapping distribution (§20) so reactivity spreads across active plugins instead of every
  parameter pulsing on every beat.
- **[DECISION]** Which visual families and themes ship, and the mutation cadence — how often a
  scene changes at all. Taste, not derivable.
- **[DECISION]** Frame-time target and floor, and the buffer-ahead threshold that triggers
  downgrade and suspend.
- Exit: `make ci` green; scheduler, grammar, mutation, deactivation, and the ladder unit-tested,
  including that a plugin swap preserves unrelated state and that the same seed reproduces a scene;
  synthetic frame-time and buffer-health traces drive the ladder through every rung and back.

### M3 — Player surface and failure hierarchy  [depends on M2]

The product-visible shell and its graceful degradation, together because each fallback tier is a
different thing rendered in the same slot.

- Persisted toggle, thumbnail beside `bottom-player__timeline`, modal presentation, and kernel
  start-and-stop tied to modal open and close.
- Lazy chunk boundary, verified absent from the initial player bundle.
- The fallback hierarchy (§22): reduced plugin graph, simple waveform, static artwork, empty
  background — with every listed failure mode routed to a tier, including WebGL unavailable, context
  loss, shader failure, blocked or dead analysis, suspended context, missing assets, unsupported
  texture format, memory pressure, invalid graph, plugin init failure, and a zero-sized canvas.
- Reduced-motion as a low-energy scene profile rather than uniformly slower animation; page-hidden
  suspension.
- **[DECISION]** Whether the visualizer is offered on mobile at all, given thermal and battery cost,
  and what the modal's presentation is at small viewport sizes.
- Exit: `make ci` green; availability-gate and fallback-selection logic unit-tested; each failure
  mode induced by hand lands on its intended tier with playback continuing; the visualizer chunk
  confirmed out of the initial bundle.

### M4 — Asset material: masks and album-art derivation  [depends on M1]

Masks and artwork together, because both are asset-to-derived-field pipelines sharing the derivation
cache, and the mask plugins are inert without the mask assets.

- In `../illuminator`: the `mask` asset type, its post-processing branch, and its type prompt
  fragment.
- A tsonu mask pack generated through illuminator, committed to `frontend/public/masks/` with a
  manifest carrying interpretation, invert, mirror, and tile behavior (§12.2).
- Album-art derivation plugins: `AlbumArtSource`, `AlbumArtPalette`, `AlbumArtEdges`, and
  `AlbumArtDisplacement`, with texture upload from the media CDN.
- Mask-driven plugins: `MaskSignedDistanceField`, `MaskContainmentField`, `MaskBoundaryField`,
  `MaskEffectStencil`, `ImageLuminanceField`.
- Derived-resource caching so one derivation serves multiple branches in a scene (§13).
- **[DECISION]** The mask library's content and count, and the illuminator style and palette it is
  generated under.
- Exit: `make ci` green; artwork drives palette, edges, and displacement, and is also provably
  ignorable; masks drive containment, stencil, and distortion with no particle system present;
  illuminator's own checks pass in that repo.

### M5 — Plugin catalog  [depends on M2, M4]

The remaining §24 initial plugins. One phase rather than four, because the contract is frozen by
here and these are additive and independently verifiable.

- Sources: `SpectrumGeometrySource`, `TransientGlyphSource`, `ProceduralTextureSource`,
  `ParametricCurveSource`, `SDFShapeSource`.
- Fields: `ProceduralVectorField`, `AudioImpulseField`.
- Simulation: `ParticleSimulator`, `ParticleEmitter`, `ParticleForceField`, `ParticleRenderer`,
  `ParticleTrailInjector`, `ReactionDiffusionSimulator`, `WaveFieldSimulator`,
  `ImpactCascadeSimulator`.
- Transformers: `SymmetryTransform`, `CoordinateWarpTransform`, `DomainWarpTransform`,
  `TilingTransform`, `EdgeContourTransform`, `ShockwaveTransform`.
- Composition: `LayerMixer`, `MaskRouter`, `FeedbackInjector`, `PaletteMapper`, `ColorTransform`,
  `GlowAndScatter`.
- **[DECISION]** `ImpactCascadeSimulator` is the one plugin here that adds contract surface: whether
  its `ImpactEvent` becomes a first-class kernel event type that any plugin may consume — feeding
  wave impulses, feedback bulges, shockwave transforms, and secondary emitters as §19.6 describes —
  or stays a plugin-local channel. This is a permanent shape choice in the plugin contract, so it
  should be settled and landed before the rest of the phase.
- Exit: `make ci` green; every plugin definition validated against graph and grammar rules by unit
  test; each renders correctly in isolation and in at least one §25 example composition; particles
  run with neither mask nor artwork present; the scheduler never activates two competing dominant
  generators; impact dynamics visibly produce acceleration, collision, fragmentation, and secondary
  field distortion.

### M6 — Diagnostics and acceptance  [depends on M3, M5]

The overlay and the acceptance sweep together, because the overlay is the instrument the sweep needs
— reproducing from seed, disabling a plugin, freezing mutation, and inspecting intermediate targets
are how most §26 criteria are actually checked.

- The `?viz-debug=1` overlay covering the full §23 readout and control set.
- A sweep of every §26 acceptance criterion, recorded pass or fail with the method used.
- A current-state `docs/visualizer.md` written once the subsystem exists, and `AGENTS.md` and
  `docs/README.md` updated to point at it.
- Exit: `make ci` green; every §26 criterion demonstrated or explicitly recorded as uncovered with
  its reason; scene reproduction from a seed confirmed identical.
